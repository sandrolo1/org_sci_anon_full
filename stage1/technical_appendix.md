# Technical supplement for organizing knowledge to change discovery

## Purpose and artifact boundary

This supplement documents the Stage 1 artifact, its evidence, and the study that would test its central claim. The submission package includes a short proposal and a reviewer edition of the prototype. The reviewer edition runs locally with invented papers and a public aggregate pilot table. Its case is an executable illustration of the proposed mechanism; it is not empirical evidence that an organized condition improves research questions. The production forum and private evaluation workbench are separate parts of the repository. Reproducing their source-level outputs requires the private bibliographic and forum exports, licensed text where applicable, a database, and model access.

The standalone reviewer ZIP contains a prebuilt site in `dist/`. After extracting it, a reviewer can run `python3 -m http.server --directory dist 8765` and open `http://127.0.0.1:8765/`; no installation or account is needed to inspect the case. To rebuild and check the bundled source from the extracted ZIP, run `npm ci`, `npm run check`, and `npm run build` with Node.js 20.19+ or 22.12+. The repository version of that source is under `web/reviewer/`, with its own `reviewer:check` and `reviewer:build` scripts run from `web/`. Neither version reads private exports, AWS, or an API key. The synthetic fixture is `public/case.json` in the ZIP. The displayed jingle and jangle **candidates** are computed from the fixture's labels and meaning fields; a candidate is never promoted to an accepted scholarly relationship by this demo. The claim check verifies exact substrings against the stored passages. An invalid quote fails the check. The novelty outcome is `insufficient_evidence`, with no numeric vote.

The artifact should be assessed as a research infrastructure prototype with preliminary runs. It should not be read as a validated construct ontology, a comprehensive novelty oracle, or a claim that one architecture already produces better science.

## Corpus identity and release control

The current novelty scoring corpus contains 10,050 CTO/TIM subset abstracts from 2015–2025. This is the declared boundary for those scores. It does not cover 2026 papers, all journals, every preprint, or all available full text. A future full eligible catalog must record the query, journal source list, dates, inclusion rules, versions, missing abstracts, and canonical paper IDs. Deduplication should use DOI and other identifiers where reliable, preserve conflicting identities as review cases, and retain the raw-source-to-canonical mapping. One paper can appear in both CTO and TIM views through separate memberships while retaining one canonical record.

For each extracted construct mention, the pipeline separates label, meaning profile, measure, unit, theoretical role, scope and passage provenance. Definition similarity, operational similarity, citation coupling and nomological patterns retrieve pairs for review. A same-label pair with divergent meanings is a possible jingle; different-label pairs with close meanings are possible jangles. Overlapping measures, shifted context, and legitimate theoretical differences are competing explanations. The dossier stores the conflicting passages and the reason a relationship remains unresolved. Discovery conditions may use only the release and relationship statuses authorized by the frozen protocol. A provisional relationship must stay visibly provisional.

The current real release has not passed all human validation gates. Source quality and extraction quality must be measured on samples before the study treats the knowledge base as validated. A conceptually validated representation is the target treatment for the main experiment, not the state of the current pilot. This distinction prevents a circular claim that the generator's own model-produced map is ground truth.

## Controlled discovery comparison

The primary estimand is the change in independently assessed question quality per fixed episode budget when condition A receives structured, source-linked conceptual records in addition to the same literature accessible to condition 0. The comparison isolates the *availability* of organization, while actual agent use is separately logged. Conditions B and C test specialization and interaction. B consists of two one-specialist variants and must not be compared with C by treating its two outputs as one. Primary outcomes should be quality per question and distinct high-quality questions per budget. Secondary outcomes include conceptual diversity, resource use, number of papers inspected, and the proportion of questions whose proposed mechanisms and predictions have traceable support.

The main experiment will preregister the release, paper perimeter, model and prompt versions, triggers, problem blocks, counterbalancing, resource ceilings, exclusion rules and analysis. Runs will be randomized within blocks. The unit of assignment is the episode. Analysis will account for multiple outputs from the same episode and distinguish within-community from cross-community problems. The original pilot's two batches are too small and heterogeneous for an effect estimate. Their scores are descriptive checks of operational feasibility. The observed generalist-minus-baseline difference is approximately +0.33 in one batch and -0.34 in the other under the older `proposal-blind-v2` rubric. Within the six matched repetitions, A exceeds 0 twice, trails twice, and ties twice.

No power calculation or definitive effect is inferred from these 30 episodes. A later sample size should be set from a prespecified minimum meaningful quality difference, estimated within-problem variation, and the cost of blind expert assessment. All runs, not only selected successful examples, must be included in the experiment ledger.

## Evaluation and falsification

Each proposed question must carry a research target, mechanism and at least one potentially distinguishing prediction. A novelty search should cover the entire eligible frozen catalog, using semantic and lexical retrieval with canonical-ID deduplication. The judge should receive a source-bound packet and compare question, mechanism and predictions to exact cited passages. It must report overlap, difference, unclear evidence, and an explicit `insufficient_evidence` state. Quote verification catches missing or wrong passages but cannot validate an interpretation. Retrieval evaluation therefore also needs known-answer cases: near duplicates, paraphrases, earlier formulations of the same question, and deliberately distinct hard negatives. Their expected relations must be set before judge outputs are seen.

Methodology assessment asks whether a proposed design distinguishes the stated mechanism from plausible rivals. A method card should separate details in the proposal from choices inferred by an agent. Impact assessment should expose at least two components: the anticipated contribution of the new question and realized uptake or citations of related prior studies. Journal tier can be used as a noisy external comparison, not the correct answer for an individual article. Model scoring, retrieval coverage, quote integrity and independent quality assessment are different properties and should be reported separately.

An automated novelty sensitivity experiment has been prepared for 38 proposals. Its 114 private packets give each proposal (i) its five semantic neighbors, (ii) those five plus five lexical candidates, and (iii) those five plus five nonretrieved controls matched approximately on year and abstract length. The two ten-paper arms isolate added lexical evidence from added reading volume more directly than five versus ten alone. The exact judge prompt, model, decoding settings, source bundle and rubric must be frozen across arms. No judge has yet run on these packets; this is a specified next test, not a result or a registered protocol. The controls are not proven irrelevant papers, so any contrast measures evidence-packet sensitivity rather than novelty accuracy.

The existing 38-proposal audit found 886 quote pairs that match recorded texts, three hybrid quote failures, and three novelty shifts of at least two points. These facts motivate the sensitivity experiment. In a separate deterministic in-corpus lexical smoke test, 1,000 of 1,000 known sources were retrieved in the top 20 from their own unaltered 20-word snippets, versus 979 after half and 323 after three quarters of the rare terms were mechanically removed. This is a source-recovery check, not a paraphrase or novelty benchmark. The expanded 2026 exercise has 125 papers, 25 per journal tier. Impact and the three-score mean increase with tier; novelty does not increase steadily. Seventy-five papers recur from the first 80-paper export, so the expansion is not independent validation. The supplied archive includes the complete saved judge answers; our offline audit matched all 2,382 card passages and 5,938 required nonblank judge quotations to source text. Most evaluated PDFs are submitted manuscripts (112 of 125). Journal tier remains a group proxy rather than article-level truth, and literal quote validity does not establish correct interpretation. A separate locked benchmark with known-answer novelty cases is needed before claiming evaluative accuracy.

## Reproducibility disclosure and safeguards

The public reviewer fixture contains four invented passages and no licensed paper text or unpublished proposal. The public pilot file contains only batch means, run counts, rubric name and SHA-256 of the private source ZIP. `submission/build_pilot_summary.py` recomputes it when that ZIP is available. Private source material is excluded from Git and should be shared only through a channel permitted by its licenses and participant agreements. The public fixture demonstrates code behavior, while the aggregate table demonstrates that real forum episodes have completed. Neither can recreate the private model calls.

For every real result intended as scientific evidence, a reproducibility manifest should include source snapshot hash, selection rules, canonical IDs, prompt and model identifiers, decoding settings, seed, tool access, retrieval ranks, passage references, attempts and failures, timing, token use, and output hashes. Where API sampling is not exactly repeatable, the saved response and the evaluation procedure still allow an auditor to inspect what happened. Model and corpus updates require new versions rather than silent replacement. Independent assessors should be blinded to treatment and should rate conceptual novelty and theoretical contribution with a codebook, agreement statistics, and documented disagreement resolution. The automated prototype is a screening and research instrument; editorial decisions and validated scholarly claims require later independent review.
